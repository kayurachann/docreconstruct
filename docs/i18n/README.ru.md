# docreconstruct — руководство на русском языке

[Английский](../../README.md) · [Вьетнамский](README.vi.md) ·
[Китайский (упрощённый)](README.zh-CN.md) · **Русский**

`docreconstruct` преобразует PDF, сканы и фотографии документов в
структурированные файлы, которые можно редактировать. Результат OCR служит
одним из источников данных для сверки, а не готовым документом. За формирование
DOCX, HTML или JSON отвечают единая модель документа, модуль компоновки и
модули вывода.

## Открытые результаты контрольного тестирования

Проверка реконструкции по эталонным данным (`oracle_reconstruction`) охватывает
**все 18 страниц** официального демонстрационного набора OmniDocBench.
Эталонные Markdown и геометрическая разметка позволяют отдельно проверить
реконструкцию, поэтому данный запуск **не является** сравнением OCR-систем.

| Результат | Измеренное значение |
| --- | ---: |
| Успешное выполнение после исправления проекции | **18/18 (100 %)** |
| Принято по всем измеряемым критериям | **2/18 (11,11 %)** |
| Сбои строгого сопоставления разметки | **0/18** |
| Оценка LibreOffice v2.2 для всех 18 страниц | **0,214798** |

Причиной прежних десяти сбоев оказалось перепутанное местами значение ширины и
высоты страницы при преобразовании разметки OmniDocBench, а не ошибка нечёткого
сопоставления текста. После исправления проекции без ослабления строгого режима
DOCX создаётся для всех 18 страниц, но только две проходят все проверки. Значит,
качество компоновщика и модуля реконструкции всё ещё недостаточно. См. [новый
отчёт и ошибки по каждой странице](../../benchmark/omnidocbench-demo/projection-0.2-metric-2.2/README.md),
а также сохранённый [исторический результат](../../benchmark/omnidocbench-demo/README.md).
Показатели версии 2.1 и 2.2 нельзя сравнивать напрямую.

В репозитории уже есть средство проверки только по исходным документам и
бесплатный локальный вариант на Tesseract. Однако сложный набор из 296 страниц
и полный набор из 1 651 страницы ещё не обработаны, поэтому заявлять
превосходство над Docling, MinerU или Marker пока нельзя.

## Веб-интерфейс и отправка файлов

После завершения развёртывания на GitHub Pages статический веб-интерфейс будет
доступен по адресу
[kayurachann.github.io/docreconstruct](https://kayurachann.github.io/docreconstruct/).
Это только интерфейс в браузере, а не готовая облачная служба обработки документов.
GitHub Pages не может запускать Python, LibreOffice, Triton, vLLM или модели OCR
на графическом ускорителе. В репозитории также нет общедоступного сервера
обработки или неограниченного бесплатного доступа к GPU.

Для работы пользователь должен выбрать сервер, которым управляет доверенная
организация. Для режима высокого качества нужны проверенный Markdown, исходный
PDF или изображение и JSON с координатами. Пользователь может загрузить готовый
JSON либо явно выбрать сетевую службу OCR, которая его создаст. До отправки
любого файла интерфейс назовёт получателя и попросит подтвердить согласие.
После изменения адреса сервера или режима OCR согласие потребуется подтвердить
снова. Срок хранения, конфиденциальность, регион обработки, лимиты и стоимость
определяет оператор.
Подробнее см. в [руководстве по производительности и развёртыванию](../PERFORMANCE.md).

## Рекомендуемый набор исходных данных

Режим высокого качества запускается только при наличии всех трёх
взаимодополняющих видов входных данных. У каждого из них своя роль:

| Входные данные | Что проект берёт из этого источника |
| --- | --- |
| Проверенный `content.md` | Точный текст и предполагаемый порядок чтения; проект не переписывает и не дополняет текст без ведома пользователя |
| Один или несколько файлов `.json` от OCR-сервиса или системы анализа макета | Соответствие страниц и блоков, координаты, типы содержимого, таблицы, формулы, оформление, оценки уверенности распознавания и сведения о происхождении данных |
| Исходный PDF или изображение | Фактический размер страницы, внешний вид, колонки, таблицы, иллюстрации и области исходного изображения |

Каждый файл JSON сначала нормализуется и сопоставляется с документом отдельно,
и только затем данные объединяются. JSON может уточнить структуру и расположение
элементов, но не заменяет текст из Markdown. Исходный файл остаётся главным
ориентиром для внешнего вида и геометрии страницы. Не относящиеся к документу
или противоречивые данные JSON отклоняются либо явно отмечаются в отчёте QA.
JSON с одним лишь извлечённым текстом недостаточен: каждый полезный блок должен
быть связан со страницей и содержать размер страницы, рамку или многоугольник
координат. Если одного из трёх источников нет, возможен лишь приближённый режим;
такой результат следует считать менее надёжным и не называть высококачественным.

### Нет JSON с координатами?

Можно открыть официальный сайт поставщика и самостоятельно выгрузить файлы или
использовать собственную учётную запись и ключ через доверенный сервер. Общий
ключ нельзя помещать в JavaScript на GitHub Pages. Лимиты, цены и правила могут
меняться; перед отправкой документа следует свериться с официальной страницей
и условиями, показанными в своей учётной записи.

| Вариант | Для чего подходит | Что важно знать заранее |
| --- | --- | --- |
| [Официальный API PaddleOCR / AI Studio](https://www.paddleocr.ai/latest/en/version3.x/inference_deployment/serving/paddleocr_official_api/overview.html) | Многоязычные сканы, искажённые фотографии, таблицы и формулы; вывод Markdown вместе с JSON | Используется доступ пользователя к AI Studio. [Текущая страница лимитов](https://ai.baidu.com/ai-doc/AISTUDIO/pmjcld5qm) указывает 3 000 страниц в сутки на каждого пользователя и каждую модель; в более длинном файле обрабатываются только первые 100 страниц. Это изменяемый лимит, а не гарантия доступности. В приведённой документации API нет отдельного срока хранения для PaddleOCR, поэтому перед отправкой конфиденциальных материалов нужно изучить действующие правила Baidu. |
| [Mistral OCR](https://docs.mistral.ai/api/endpoint/ocr) | Сложные страницы, структурированный Markdown и координаты | Нужен собственный ключ, а файл отправляется в Mistral. [Цена](https://mistral.ai/pricing/api/) рассчитывается по страницам; пробные квоты и ограничения зависят от учётной записи и не означают гарантированную бесплатную обработку. [Режим без хранения данных](https://help.mistral.ai/en/articles/347612-can-i-activate-zero-data-retention-zdr) доступен лишь для подходящих платных планов и не охватывает все способы загрузки файлов и пакетной обработки. |
| [Mathpix](https://docs.mathpix.com/) | Формулы, естественно-научные материалы и рукописный текст | [Бесплатной пробной версии нет](https://website.mathpix.com/docs/convert/billing); взимаются плата за подключение и плата за использование. Mathpix требует [не раскрывать секретные ключи в коде браузера](https://docs.mathpix.com/reference/authentication), поэтому для PDF нужен доверенный сервер. Согласно [правилам хранения](https://docs.mathpix.com/concepts/data-retention), исходные изображения сейчас могут храниться до 30 дней, а распознанный текст — до 90 дней. |
| [Azure Document Intelligence](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout?view=doc-intel-4.0.0) | Формы, таблицы, порядок чтения, Markdown и многоугольники координат | Нужны собственный ресурс Azure и учётные данные. [Лимит F0](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/service-limits?view=doc-intel-4.0.0) сейчас составляет 500 страниц в месяц, но в одном запросе обрабатываются только первые две страницы. Microsoft сообщает, что данные анализа временно хранятся в выбранном регионе и [удаляются в течение 24 часов](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/faq?view=doc-intel-4.0.0). |
| [Google Document AI](https://docs.cloud.google.com/document-ai/docs/overview) | Корпоративные документы, формы и подробная геометрия | Нужны проект Google Cloud, обработчик, платёжный аккаунт и права OAuth. По [действующей странице цен](https://cloud.google.com/products/document-ai/pricing) первые 1 000 страниц Enterprise Document OCR в месяц для одной учётной записи не тарифицируются, затем действует оплата по объёму. Google заявляет, что [не использует документы и результаты клиентов для обучения Document AI](https://docs.cloud.google.com/document-ai/docs/security). Проект преобразует возвращённый Document JSON в Markdown. |
| [OCR.space](https://ocr.space/ocrapi) | Короткие неконфиденциальные файлы, отправляемые прямо из браузера | Бесплатный план сейчас ограничен 500 запросами в сутки с одного IP, 25 000 в месяц, размером 1 МБ и тремя страницами PDF; гарантии доступности нет. Следует использовать личный ключ: ключ в браузере всё равно можно скопировать и исчерпать его квоту. Поставщик заявляет, что не хранит исходные файлы и текст OCR. |
| [olmOCR](https://github.com/allenai/olmocr) | Сложные PDF, рукописный текст, математика, таблицы и многоколоночный порядок чтения | Код Apache-2.0 не предоставляет бесплатные вычисления на чужом сервере. Для локального запуска нужен подходящий GPU, а внешние службы вывода оплачиваются отдельно. [Онлайн-демонстрация](https://olmocr.allenai.org/) предназначена для пробы; опубликованного производственного API и гарантии доступности у неё нет. |
| [Публичная демонстрация в Hugging Face Spaces](https://huggingface.co/spaces/PaddlePaddle/PaddleOCR-VL-1.6_Online_Demo) | Проверка модели перед выбором способа развёртывания | [ZeroGPU](https://huggingface.co/docs/hub/main/spaces-zerogpu) даёт небольшое число GPU-минут в сутки в зависимости от типа аккаунта, использует очередь и ограничивает время выполнения; [выделенные конечные точки вывода](https://huggingface.co/docs/inference-endpoints/en/pricing) платные. Публичную демонстрацию нельзя использовать как скрытый производственный сервер проекта. |

В проекте `paddleocr_official` читает `PADDLEOCR_ACCESS_TOKEN` и отправляет
асинхронное задание в AI Studio по контракту [официального комплекта средств](https://www.paddleocr.ai/latest/en/version3.x/inference_deployment/serving/paddleocr_official_api/python.html).
Это не то же самое, что `paddleocr_vl_server`: второй вариант соединяется с
сервером PaddleOCR-VL, который выбрал и обслуживает оператор. Оператор может
опубликовать небольшой список через `DOCRECONSTRUCT_PUBLIC_OCR_PROVIDERS`.
`/v1/hybrid/capabilities` отмечает доступными только разрешённые и настроенные
службы и не возвращает ключи, токены или закрытые адреса.

По умолчанию номера страниц в источниках должны совпадать точно. Сопоставление
по порядку допускается лишь тогда, когда обе последовательности полные,
непрерывные и содержат одинаковое число страниц. Например, так можно связать
страницы 5–6 из результатов OCR с двумя фрагментами исходника, пронумерованными
как 1–2. Такое сопоставление всегда отмечается предупреждением в отчёте
проверки. Проект не пытается угадывать соответствия для неполных или
нерегулярных последовательностей. Единицы координат и сведения о
предварительной обработке от каждого OCR-сервиса сохраняются, чтобы положение
элементов можно было корректно пересчитать относительно исходной страницы.

```powershell
docreconstruct hybrid content.md original.png `
  --evidence paddleocr.json `
  --evidence mineru.json `
  --output output/result.docx `
  --qa-report output/result.qa.json
```

Параметр `--evidence` можно указать несколько раз, чтобы использовать
независимые результаты распознавания. Если структуру JSON не удаётся определить
однозначно, явно укажите OCR-сервис вместо автоматического выбора:

```powershell
docreconstruct hybrid content.md original.pdf `
  --evidence result.json `
  --evidence-provider result.json=paddleocr `
  --output output/result.docx
```

### Многостраничные оригиналы

Многостраничный PDF анализируется и компонуется постранично. Каждая страница
оригинала становится отдельным разделом Word со своим физическим размером и
обязательным переходом на новую страницу. Смысловая группа может продолжаться
на следующей странице, если это подтверждают независимые привязки к оригиналу.
Пустая страница или страница, пропущенная OCR, сохраняется как пустой раздел, а
не заполняется содержимым со следующей страницы. Обычная QA-проверка сверяет
число запланированных разделов, а явно включённая проверка через LibreOffice
дополнительно требует точного совпадения числа отрисованных страниц с
оригиналом.

```powershell
docreconstruct hybrid complete-document.md multi-page-original.pdf `
  --evidence provider-result.json `
  --output output/complete-document.docx `
  --qa-backend libreoffice `
  --qa-report output/complete-document.qa.json
```

## Быстрая установка

```powershell
python -m pip install -e ".[hybrid]"
docreconstruct hybrid content.md original.png -o output/result.docx
```

LibreOffice запускается только тогда, когда пользователь явно включает
рендеринг документа для визуальной проверки:

```powershell
docreconstruct hybrid content.md original.png -o output/result.docx `
  --qa-backend libreoffice `
  --min-visual-score 0.80 `
  --qa-report output/result.qa.json
```

## Ограничения, требующие ручной проверки

- OCR или Markdown могут пропустить фрагменты либо неверно распознать написание,
  диакритические знаки, числа, пунктуацию, научные обозначения, математические
  операторы и рукописный текст.
- Формула может остаться редактируемой, но содержать ошибку в операторе,
  скобках, точке выравнивания, положении предела или переносе строки.
- Таблицы, колонки, порядок чтения, шрифты, интервалы, иллюстрации, колонтитулы
  и разбиение на страницы могут отображаться по-разному в оригинале,
  Microsoft Word и LibreOffice.
- Оценки уверенности OCR и успешное прохождение автоматической QA-проверки —
  полезные ориентиры, но не доказательство правильности математического,
  юридического или другого профессионального содержания.
- Если Markdown расходится с оригиналом, комбинированный процесс сохраняет
  формулировки из Markdown и не пытается самовольно угадать или исправить текст.
- Точное совпадение с оригиналом на уровне пикселей и глубокое редактирование с
  помощью встроенных объектов Word иногда требуют взаимоисключающих решений.
  Проект не гарантирует воспроизведение 1:1 для любого документа.

Перед использованием результата при проведении экзаменов, работе с архивными
материалами, а также в юридических, медицинских, финансовых, нормативных и
